## 后端能力回退（硬性规则）

- 当前使用第三方/开源模型 API 时，部分「官方后端能力」可能不可用（典型的：图片识别、联网搜索、代码执行等）。
- 如果 agent 的内置工具/后端能力调用失败或不支持（比如 `web__run` 报错、`image` 输入被拒、`tool` 不可用），必须立即自动改用等效的**前端/MCP 工具**，如 `analyze_image`、`web_search` MCP 等。
- 优先顺序：官方后端（如可用）→ MCP 工具 → 返回明确失败信息。
- 绝对不允许在能力缺失时编造响应（AI 幻觉）。必须如实告知用户：哪些能力不可用、原因是什么、已尝试了哪些替代方案。
- subagent 同样适用此规则。
- 特例：用户明确指定使用某 API 且接受其限制时，遵循用户指令。

## 信息检索与用户指定源

- 用户指定检索源（如"去 gh 找""去 xxx 查"）时，必须直接去该源检索，不得跳过或依赖内部知识替代。
- 权限、网络等阻塞导致无法访问指定源时，明确告知用户具体阻障，不默默 fallback 到其他来源。
